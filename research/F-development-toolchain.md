# F · Development toolchain

**Reviewed November 12, 2026**

## Daily workflow

Start with Git, a pinned Node toolchain and lockfile, Claude Code or another local coding assistant, Playwright Test, Vitest, Blender, and a source-controlled pack validator. A browser MCP helps exploratory inspection. The test runner and CI remain the release evidence. The game runtime only needs its provider API and normal application interfaces. [Claude Code quickstart](https://code.claude.com/docs/en/quickstart), [Playwright installation](https://playwright.dev/docs/intro), [Vitest](https://vitest.dev/guide/), [Blender LTS](https://www.blender.org/releases/4-5/)

- Put architecture boundaries, verification commands, versioned blueprint references, and fixture rules in a short root `CLAUDE.md`. Keep durable rationale in the research and decision register, and use `.claude/rules/` for path-specific content and test rules. Use plan mode when engine contracts, migrations or cross-module ownership could change. Use direct execution for a scoped fix. Verify loaded memory with `/memory`. [Claude Code memory](https://code.claude.com/docs/en/memory), [Best practices](https://code.claude.com/docs/en/best-practices)
- For a feature, supply acceptance criteria, a real input/output example and a target fixture. Use short-lived worktrees if a renderer, evaluator and pack can proceed on separate file ownership. Keep data contracts explicit and integrate through reviewed changes. A read-oriented Explore or independent reviewer can help with verbose discovery and review. Use scoped roles and avoid sharing provider credentials across worktrees. [Claude Code common workflows](https://code.claude.com/docs/en/common-workflows), [Git worktree](https://git-scm.com/docs/git-worktree), [Claude Code subagents](https://code.claude.com/docs/en/sub-agents)
- Put required verification in ordinary CI: format/type checks, pack schema validation, deterministic replay, authorization tests and Playwright flow checks. Use hooks for small, predictable local checks and permission guards, with failures surfaced. Model review may run as an isolated advisory pass with pinned CLI and validated JSON output. A dedupe key can combine file, anchored location and issue category. Untrusted PR text stays data. Limit tokens and permissions, and keep secrets away from untrusted forks. [Hooks](https://code.claude.com/docs/en/hooks), [Headless CLI](https://code.claude.com/docs/en/headless), [Claude GitHub Actions](https://code.claude.com/docs/en/github-actions), [GitHub Actions security hardening](https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions)
- Browser tests use a fixed seed and reduced motion for replay. Check drag and its selection alternative, focus restoration, keyboard-only runs, dynamic trace announcements and mobile layouts. Take separate snapshots of art and UI so a renderer change does not hide interaction breakage. Include manual keyboard and screen-reader testing. [Playwright accessibility testing](https://playwright.dev/docs/accessibility-testing), [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- Keep a local source inventory with publisher, date, URL, version, claim and checked-on date. Use a scheduled CI link and version check after the first pack, with manual review of redirects and changes. Content writers review the current guide and exact SDK/API behavior before publishing. [CCAR-F guide](https://github.com/Amey-Thakur/CLAUDE-CERTIFICATIONS/blob/main/architect-foundations/exam-guide.pdf), [Claude Code releases](https://github.com/anthropics/claude-code/releases)

Claude Code-specific frontmatter and cloud Skills upload have different compatibility constraints. Pin the target, read `SKILL.md` and bundled scripts before enabling, and keep credentials out of the prompt. `allowed-tools` in Skills can preapprove calls. Enforce permissions through the host and explicit tool policy. There is little reason to install a broad third-party “game development” or “security” Skill before identifying a gap in the current workflow. [Claude Code Skills](https://code.claude.com/docs/en/skills), [Claude Code permissions](https://code.claude.com/docs/en/permissions)

## MCP shortlist

| Integration | Priority and verified setup | Access and tradeoff |
|---|---|---|
| **Microsoft Playwright MCP** | Useful for local interactive QA. Repository release v0.0.85 dated November 9. Follow the official install/config reference and pin the npm version. Keep Playwright Test as the repeatable CI mechanism. [Setup](https://github.com/microsoft/playwright-mcp), [releases](https://github.com/microsoft/playwright-mcp/releases) | Use an isolated browser profile with local/staging sites and synthetic accounts. Browser navigation, credentials, downloads and unsafe execution permissions matter. Expose only needed capabilities and keep production sessions elsewhere. |
| **GitHub MCP** | Optional when the assistant needs read access to cross-repo issues, Actions or review context. GitHub's v2.1.0 release is dated November 3. Prefer Git and `gh` where sufficient. [Official setup and toolsets](https://github.com/github/github-mcp-server), [releases](https://github.com/github/github-mcp-server/releases) | Read-only toolsets and fine-grained repository-scoped credentials. Use explicit authorization for writes. Treat issue comments and files as untrusted content. |
| **Figma MCP** | Useful once an actual Figma design file is the design source. Figma maintains remote and desktop options and plan/seat limits. [Official setup](https://developers.figma.com/docs/figma-mcp-server/), [seat and access guidance](https://help.figma.com/hc/en-us/articles/32132100833559-Guide-to-the-Figma-MCP-server) | Authenticate to selected files and fetch frames, tokens and layout context. Use the review source for UI. Blender remains the scene and asset authority. |
| **Supabase MCP** | Defer initially. Local CLI and migrations offer more predictable review. The maintained official setup exposes project scoping, read-only mode and feature selection. [Supabase MCP setup](https://supabase.com/docs/guides/ai-tools/mcp), [CLI releases](https://github.com/supabase/cli/releases) | If adopted, authenticate to a development project only, enable read-only and the needed feature groups, and use synthetic data. Verify current behavior against the CLI and DB. |
| **Docs and research** | Prefer official browser docs, source links and the source inventory. Claude Academy publishes a course MCP for its own material. [Claude Academy MCP](https://academy.claude.com/help/mcp) | Add a docs connector only when retrieval is a real bottleneck. Keep the official guide and release-date crosswalk. |
| **Filesystem, issue tracking, asset storage and observability MCP** | Defer. Git, repository files, existing issue workflows and named log queries meet initial needs. | Additional connectors expand access and maintenance. Evaluate a named workflow with a specific read/write scope before adoption. |

Use documented `claude mcp add` options and confirm `claude mcp list` after configuration. Put intentionally shared, inspected project settings in `.mcp.json` and personal experiments in user scope. Reference environment variables rather than including tokens. For a remote connection, use the vendor's supported auth and least-access permissions. Review servers and updates before granting capability. [Claude Code MCP](https://code.claude.com/docs/en/mcp), [MCP security guidance](https://modelcontextprotocol.io/specification/latest/basic/security_best_practices)

## Design, assets and QA

| Task | Tool and setup source | Workflow |
|---|---|---|
| World and characters | [Blender LTS](https://www.blender.org/releases/4-5/), [orthographic camera](https://docs.blender.org/manual/en/latest/render/cameras.html), [glTF export](https://docs.blender.org/manual/en/latest/addons/import_export/scene_gltf2.html) | One reusable model kit, rig and lighting scene. Export bakes for sprites and an optional glTF test scene if comparing true 3D. Use animation state tables and an anchor manifest. |
| Layout and atlases | [Tiled](https://www.mapeditor.org/), [Phaser sprites](https://docs.phaser.io/phaser/concepts/gameobjects/sprite), [TexturePacker](https://www.codeandweb.com/texturepacker) | Start with layout JSON or Tiled and a repeatable atlas build. Evaluate commercial packing only if the handoff or compression becomes a bottleneck. |
| UI and sound | [Figma](https://www.figma.com/design/), [Audacity](https://www.audacityteam.org/) | Prototype the route editor and focus behavior. Edit original or licensed loops, normalize relative levels and check sound-off comprehension. |
| Art exploration | [OpenAI image generation docs](https://developers.openai.com/api/docs/guides/image-generation), [Poly Haven license](https://polyhaven.com/license), [Kenney asset terms](https://kenney.nl/support) | Optional art-direction boards, placeholders and texture studies. Use rights-cleared inputs, record license and generation provenance, and rebuild final key shapes and animations in a common pipeline. |
| Review and delivery | [Playwright Test](https://playwright.dev/docs/intro), [Vitest](https://vitest.dev/guide/), [GitHub Actions](https://docs.github.com/en/actions), [OpenTelemetry JS](https://opentelemetry.io/docs/languages/js/) | Smoke-test every published pack, record device performance and fixture parity, and preserve real test reports. |

The inventories establish documented functionality and recent repository activity where shown. Tool installations, account access and version compatibility were not exercised in this research workspace.
