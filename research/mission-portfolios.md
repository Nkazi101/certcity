# Certification mission portfolios

The city uses the four July 2026 v1.0 Claude exam guides. The [guide inventory](claude-certification-integration.md) links the original PDFs and the December guides used for the revised Academy rehearsals and workshops.

There are 34 missions across four pathways. Dispatch has its purpose-built work surface. Six dedicated labs let learners operate a shared Project, proof stream, retrieval bench, clean checkout, receiving counter or research table. The other 27 assignments open a workbench with a stakeholder request, inspectable records, editable settings or draft fields, and a sample replay. Learners see a second case after their sample passes and can save after both replays meet the acceptance conditions. Practicals use synthetic inputs and deterministic test fixtures.

The workbench depends on the assignment. Enrollment uses a message inbox with an individual reply preview. The bulletin has separate working documents and an approval tray. Invoice and refund work use ledgers that show the previous value beside the working entry. Application privacy uses a redaction sheet where each field can be removed or restored. The permit integration uses the actual arrival order of returned results and lets learners link them to request IDs before inspecting the assembled message. Queue assignments group live, archive and review decisions by destination. Architecture work uses policy matrices, evaluation boards and a timed incident sequence with a handoff draft. The case-file hotspot exposes the records needed at the desk. The corresponding room stations use document trays, ledgers, consoles or planning boards, and City impact records what happened on the second case.

## Progression

Players select a credential and explore the shared city. The journal lists available work and the named prerequisite for each later mission. A prerequisite is satisfied by saving a replay that meets its operational requirements. Core missions advance on saved city work. The two CCAR-F challenge variants also require evidence on named prerequisites. A first-seen correct response or reviewing its explanation satisfies the challenge gate. Review unlocks practice without adding independent correct-answer credit.

CCAR-F starts at City Dispatch, Central Library, Printworks, and Juniper Kitchen. The core Dispatch repair opens a room-booking assignment that requires both safe routing and pre-action checks. Central Library opens an archive coordination assignment with partial worker results. Both chains lead to the peak shift, where retries, handoff, and ambiguity routing interact under a deadline, a two-hour support limit, and a spend cap. The invoice and release chains lead to the market rush, where real-time confirmations compete with batch work and human review has a fixed capacity. These are authored progression choices. The degree of challenge has yet to be calibrated with learners.

## Replay and city impact

The metrics are synthetic and apply to the period shown. Workbenches show concrete differences such as a held invoice, a linked tool result, an approved draft, or an exhausted review allowance. A saved prior replay remains accessible when a learner returns to work done with the earlier experience. Saving an updated outcome replaces the displayed outcome for that assignment.

## Mapping and assessment

Each mission links published objectives to technical sources and original multiple-choice or multiple-response items. The debrief connects the applied setup to those concepts, and the answer key and rationale appear after submission. City application means a successful saved rehearsal on the workbench’s mapped objectives. First-seen checks and follow-ups show separate exam-style practice evidence. Earlier prototype results remain readable. Coverage samples the published objectives in representative situations.

Each assignment uses the same four visible milestones. Save a successful city replay, confirm the technical debrief, submit the assignment’s exam check, and return for held-out practice seven days after that check. A follow-up presents one held-out item for each exam domain represented in that mission. It is domain-level retrieval practice and does not claim to retest every objective. Existing saved checks without a timestamp remain reviewable; the learner can submit a fresh check to start the follow-up interval. The assignment check and follow-up remain separate from the official exam. Anthropic states that its exams use multiple-choice and scenario-based multiple-response items and gives a 120-minute response window. [Partner Academy FAQ](https://anthropic-partners.skilljar.com/page/faq-certifications)

Every mission has a stakeholder briefing and a work area. In the 33 standard interiors, learners can visit each stakeholder, open the case file, and use the work area from the room. Dispatch has its own cutaway and station flow. The Certification practice dialog uses the same four rows, completion states, and optional Exam Lens across assignments. Learners can complete the assignment, debrief, and exam check in any order. The journal groups follow-ups by availability and opens their questions seven days after each check. Exam Lens exposure is recorded so a previously seen item cannot count as first-seen mission-check evidence. ## CCAR-F assignment work surfaces

Dispatch provides the reference for linking a visible case, a control and its result. Juniper Kitchen, the Printworks proof release and archive coordination have dedicated labs. The other workbenches expose source records and independently editable settings. All replays use synthetic fixtures.

| Assignment | Work surface and learner action | What the replay makes visible |
|---|---|---|
| Reopen the reference desk | Inspect an unfinished tool-use trace, distinguish a read connector from a draft-writing connector, and compose an auditable exhibit note from source-linked claims. | Whether the tool result returns in the conversation and whether unlike attendance claims stay separate. |
| Standardize proof releases | Move instructions between project and user scope, link a supporting example from a manually invoked Skill, and set the two proof test paths in the repository. | Compare both shifts and open an individual file. A clean checkout shows which of the three files load the paper-size rule. |
| Catch bad supplier invoices | Pair two source documents with expected outputs. Set nullable integer cents and line reconciliation independently. Choose what happens to each exception. | The same batch shows whether invoice 303 reached the ledger, whether an unreadable mark was recorded as blank, and what happened to the date and contradictory totals. |
| Fix room-booking handoffs | Gate a write on service verification, place pre-tool and post-tool hooks on a call path, and route two different tickets. | Whether an unauthorized change is blocked, read output is normalized, and staff receive a useful handoff. |
| Recover a partial archive search | Assign the south ward, retain completed work, build separate requests for maps and register workers, then assemble the editor’s brief from a partial-results replay. | The dispatch report identifies missing packet fields by worker. The brief shows the evidence, the two unchecked wards and the exhausted retry. |
| Review the order-system migration | Pick which callers to exercise from the dependency trace, split two trials from the same commit, set both normalizer expectations and assemble the next operator’s handoff. | Which dependency paths and expected outputs are covered and what survives when another operator resumes. |
| Give the repair desk the right tools | Change a role-capability matrix, configure shared versus personal MCP settings, and navigate from search to one inspected call site. | Whether triage has only the necessary status capability and a clean checkout can discover the shared connector. |
| Make review useful at the release gate | Configure a noninteractive CI runner, enter the tolerance in millimeters, define finding identity and choose who reproduces the integration issue. | Whether the allowed offset is handled correctly and the integration mismatch is reported without retry duplicates. |
| Keep vendor records reliable at closing | Route the deadline-bound request and batch queue separately, restore dates by order/source IDs, and allocate ten audit slots by form type. | Deadline, result correlation, review capacity, and high-confidence handwriting risk. |
| Keep the peak shift within capacity | Set a deadline-bounded retry rule, route remaining unknowns with attempt history, and separate human requests from ambiguous matches. | Recovery, staff minutes, lookup spend, unresolved work, and safe customer handling. |
| Run the vendor rush | Schedule live and batch work against a cost cap, reload each date by order ID, and fit handwriting plus calibration samples into the review window. | Queue lateness, spend, date accuracy, review minutes, and discrepancies that would otherwise pass. |

This division follows the exam objectives and proposed practical mechanics in the [CCAR-F certification blueprint](D-certification-blueprint.md), and the city’s purpose-built room guidance in [visual direction](C-visual-direction.md). The design treats task-specific interaction as a product rationale; the cited simulation review does not establish learning gains for this product. Those gains still require learner evaluation. [Chernikova et al., 2020](https://doi.org/10.3102/0034654320933544) · [CertCity validation plan](G-mvp-plan.md)

The scripted stakeholder questions keep each case reproducible. Each person gives a different relevant perspective; the learner asks the offered question, records the reply in the case notes, inspects the evidence, and then configures the system. The dialogue is authored from that mission's evidence and does not generate new facts at runtime. Simulation research supports scaffolding and feedback as design elements across studied higher-education tasks; it does not establish that CertCity improves certification results. That needs learner evaluation. [Chernikova et al., 2020](https://doi.org/10.3102/0034654320933544) · [CertCity validation plan](G-mvp-plan.md)

The validator checks that every published objective is reachable in the prerequisite graph, that every exam mapping resolves, that the mapped question IDs are unique within a pathway, and that advanced replays distinguish the intended configuration from alternatives. The [CCAR-F research blueprint](D-certification-blueprint.md) records the more granular guide bullets and proposed evidence. The [integration research](claude-certification-integration.md) covers original item writing, feedback, and the limits of inferring readiness.

## Rationale for the three rebuilt work areas

| Decision | Evidence and how it applies |
|---|---|
| Start in the building with a person reporting the problem. | The design brief places people and evidence at the affected station. In the rebuilt rooms, the person starts the conversation and the player can go directly to the work or ask a relevant question. The room exposes the same targets as buttons for keyboard and touch use. [Simza visual direction](C-visual-direction.md) · [W3C pointer alternatives](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) |
| Keep the object and result visible as the learner changes one setting. | Dispatch demonstrates the design in this product. Direct manipulation research explains the value of incremental, reversible changes to a visible object with immediate results. Simulation research supports feedback and scaffolding across studied tasks. The specific visual treatment is a design choice that still needs learner evaluation. [Direct manipulation research](https://hci.ucsd.edu/hollan/direct-manip.pdf) · [Simulation meta-analysis](https://doi.org/10.3102/0034654320933544) · [Functional alignment in simulation](https://pubmed.ncbi.nlm.nih.gov/24448038/) |
| Keep extraction shape and ledger validation independent. | The schema permits an integer with an incorrect amount. The modeled ledger compares the amount with the trusted line sum. The example tray has two slots because the authored case targets a specific contrast between an unreadable field and a blank. It represents a fixed fixture, so a preview does not predict how a live model will generalize. [Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) · [Claude prompting guidance](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) |
| Model a repository through its files and a second operator. | Claude Code applies project and user instructions at different scopes, loads path rules for matching files, and supports linked examples in a Skill. The learner can inspect the result with and without Riley’s personal settings. The replay covers the three named files in the case. [Claude Code memory and rules](https://code.claude.com/docs/en/memory) · [Claude Code Skills](https://code.claude.com/docs/en/skills) |
| Model delegation and synthesis as separate steps. | Anthropic’s engineering account describes independent worker contexts, explicit scopes and output requirements. The assignment shows why the missing coverage needs a map worker and why the editor needs the partial findings plus the gap and retry record. [Anthropic multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) · [CCAR-F blueprint](D-certification-blueprint.md) |
| Keep independent exam evidence separate from rehearsal. | The Lens can give immediate explanations. The mapped skill check uses separate item IDs, with response counts and rationales. Later practice is scheduled from the first scored check. Readiness still requires independent review and learner evidence. [Original item and practice design](claude-certification-integration.md) · [Testing Standards](https://www.apa.org/science/programs/testing/standards) |

## Sources for the implementation

- Decision boundaries and bounded control are based on Anthropic’s description of workflows, agents, and task patterns. [Building effective agents](https://www.anthropic.com/research/building-effective-agents)
